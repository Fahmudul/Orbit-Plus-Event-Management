# Orbit Plus — Test Plan

## Purpose

The purpose of testing is to verify that Orbit Plus satisfies its approved functional requirements, acceptance criteria, role permissions, and non-functional quality expectations.

## Testing Scope

Testing covers:

- Authentication.
- Event discovery.
- Event registration.
- Organizer event management.
- Participant management.
- Volunteer attendance.
- Sponsorship submission and analytics.
- Administrative approval and monitoring.

## Testing Types

### Functional Testing

Verifies that each workflow produces the expected result.

### Validation Testing

Verifies that required fields and invalid inputs produce clear messages.

### Role-Access Testing

Verifies that users can access only the functionality permitted for their role.

### Usability Review

Checks whether the interface and workflow are understandable.

### Requirement-Based Testing

Maps test cases to user stories and functional requirements.

## Test Statuses

The following statuses are used:

- Not Executed
- Passed
- Failed
- Blocked

## Evidence Rules

Test results must not be marked as passed before execution.

Each executed test should record:

- Execution date.
- Tester.
- Test data.
- Actual result.
- Final status.
- Screenshot or other evidence when available.
