# Sprint 2 — Organizer Module

## Sprint Goal

Represent the organizer workflow from account application and approval through event and participant management.

## Planned Scope

- Organizer application.
- Administrative approval.
- Organizer dashboard.
- Event list.
- Event creation.
- Required-field validation.
- Event publication.
- Event editing.
- Participant-list management.
- Registration-status management.
- Participant export.
- Last-minute communication.
- Organizer profile management.

## Selected Requirements

- US-07 through US-10
- FR-16 through FR-19

## Acceptance Conditions

- An organizer application contains the required information.
- Approval is required before an organizer can go live.
- An approved organizer can create events.
- Required event information is collected.
- Unpublished events do not appear in public discovery.
- Organizers can edit their own events before the event date.
- Organizers can view and manage participant information.
- Export and communication actions are represented.
- Organizer profile information can be updated.

## Sprint Review Result

The organizer module represents the primary SRS workflows without introducing unrelated features such as ticket scanning, financial dashboards, certificates, or marketing automation.

## Retrospective Notes

- Major event changes should be communicated clearly.
- Organizer and administrator permissions must remain separate.
- Existing reusable components should be preferred.
