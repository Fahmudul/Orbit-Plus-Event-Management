# Sprint 1 — Public, Authentication and Participant

## Sprint Goal

Represent the participant journey from account registration through event discovery, registration, and registration management.

## Planned Scope

- Public event discovery.
- Authentication.
- Participant registration.
- Event details.
- Event registration review.
- Registration confirmation.
- Participant dashboard.
- Registration cancellation.
- Notifications.
- Participant profile.

## Selected Requirements

- US-01 through US-06
- FR-01 through FR-15

## Design Evidence

- REPORT-01 — Participant Registration
- REPORT-02 — Event Discovery
- REPORT-03 — Event Details
- REPORT-04 — Registration Summary
- REPORT-05 — Participant Dashboard

## Acceptance Conditions

- Participants can register and log in.
- Published events can be searched and filtered.
- Event details contain the required information.
- Registration information is reviewed before confirmation.
- Registration status is visible.
- Cancellation follows the defined deadline.
- Unsupported participant functionality is not introduced.

## Sprint Review Result

The main public, authentication, and participant workflows are represented in the Figma design and mapped to the approved requirements.

## Retrospective Notes

- Requirement mappings should remain concise.
- Navigation must contain only SRS-supported destinations.
- Registration status terminology must remain consistent.
